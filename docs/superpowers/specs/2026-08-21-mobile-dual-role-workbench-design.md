# 移动端教师与家长工作台设计

## 目标与边界

本次重构将现有单页桌面工作台替换为移动优先的双角色应用。打开应用先选择身份；教师和家长进入完全不同的信息结构，但共享同一套“课堂时刻牌”视觉语言。

产品仍是合成演示数据：支付始终标示为模拟支付；AI 只生成待确认草稿；服务端继续作为课程、课时和订单状态的唯一来源。

首版家长端只展示当前演示账户关联的一个孩子。教师端新增手动学生管理和手动排课。课程时长固定为 60 分钟，开始时间精确到分钟。

## 视觉方向：课堂时刻牌

**核心机制**：课程不是一组漂浮卡片，而是一张可扫描、可更新的分钟级时刻牌。时间、学生、年级与状态固定对齐；只有状态变化才产生一次克制的翻页动画。

### 不可违反的设计约束

- 不使用渐变英雄区、统计卡片墙、玻璃拟态、通用仪表盘或无意义图标网格。
- 不让每个内容块都拥有相同圆角、阴影和标题。只有订单、支付确认等真正独立的实体可使用容器。
- 结构必须来自真实任务：行列对应课程，时间轨道对应分钟，抽屉对应待处理对象，底部操作台对应新增或编辑。
- 动效只用于身份牌切换、课程状态更新和底部操作台开合；支持减少动态效果偏好。
- 桌面端是移动工作台的宽屏延展，不恢复成旧式多栏后台。

### 令牌

| 用途 | 值 | 说明 |
|---|---|---|
| 时刻牌底色 | `#15191B` | 教师课程轨道与重要状态 |
| 字符米白 | `#F4F0E5` | 时刻字符与浅色背景 |
| 信号琥珀 | `#E6A63C` | 当前课程、可操作重点 |
| 取消红 | `#C94A42` | 取消、冲突、不可用 |
| 家长深蓝 | `#14364D` | 家长端秩序感与文字 |
| 家长浅青 | `#DDEEE8` | 孩子信息与连续记录背景 |

字体采用设备可用中文无衬线；课程时间使用等宽数字回退栈，以保证分钟列稳定。大字号只用于当前时间或当前课程，不用于营销式标题。

## 信息架构

```
身份选择
├─ 教师端
│  ├─ 今日（默认）
│  ├─ 课表
│  ├─ 学员
│  └─ 订单
└─ 家长端
   ├─ 孩子主页（默认）
   ├─ 课程记录
   └─ 课包与订单
```

### 身份选择

首次打开没有默认角色。屏幕中间是一块双面的“教师 / 家长”翻页牌；选中角色后记住当前会话，顶部仍保留“切换身份”。两种身份不共享底部导航和首屏内容。

### 教师端

**今日**是主入口，不展示汇总卡片。顶部为日期、刷新和当前状态；主体是按时间递增的课堂行。每行显示开始时间、学生姓名、年级和课程状态。右下角的主操作为“手动排课”；AI 草稿入口为次级操作。

**课表**是七天浏览器。它以纵向分钟轨道展示当天课程，在窄屏一次聚焦一天；切换日期不会压缩成难读的七列表格。宽屏可同时显示七日，但仍沿用同一时间轴。

**学员**是可检索名单，不是课时卡片网格。点开学生进入档案抽屉，显示年级、课时账目和近期课程。新增与编辑在底部操作台完成；删除采用归档语义，保留历史课程、订单和课时审计。

**订单**仅可查看家长发起的模拟订单，明确说明教师不能确认支付或直接加课时。

### 家长端

家长主页只对应一个孩子。首屏以“下一节课”为锚点，依次连接可用课时、即将上课、已上课程和订单，而非堆叠信息卡。购买课包进入模拟订单确认；付款按钮和结果必须持续显示“模拟支付”。

## 核心交互

### 手动学生管理

教师可新增、查看、编辑和归档学生。字段为姓名、年级和关联家长演示账户；姓名与年级必填。归档学生从活跃名单移除，但历史课程、订单和课时数据仍可审计。若该学生是家长端唯一关联学生，家长端显示明确的无可用学生状态。

### 手动排课与编辑

教师在底部操作台依次选择：学生（可多选）、日期、开始时间、课程名称。时间控件使用原生时间输入或等价可访问控件，`step=60`，允许任意 `HH:mm` 分钟值。可选择多个学生，但服务端必须验证所有学生同年级、可用课时大于零且老师没有时间冲突。

已排课程可编辑学生、日期与开始时间，或取消；编辑在提交前重新执行全部冲突和课时规则。已完成课程不可删除或直接改时间，避免篡改已消耗课时；发生录入错误时只允许通过受控更正流程处理，首版不提供该入口。

### AI 草稿

AI 请求只产生虚线“待确认”课程行，不会覆盖手动排课。草稿与手动排课共用同一课程校验与确认流程；AI 不可用时，手动排课仍完全可用。

## 服务端与数据契约

现有只读学生接口需扩展为受教师角色保护的 CRUD 接口：

| 方法 | 路径 | 行为 |
|---|---|---|
| `GET` | `/api/teacher/students` | 仅返回未归档学生 |
| `POST` | `/api/teacher/students` | 新增学生 |
| `PATCH` | `/api/teacher/students/:id` | 修改姓名或年级 |
| `DELETE` | `/api/teacher/students/:id` | 归档学生，返回归档后的资源 |
| `POST` | `/api/teacher/lessons` | 创建手动或经确认的 AI 课程 |
| `PATCH` | `/api/teacher/lessons/:id` | 编辑已排课程的学生、开始时间或名称 |
| `POST` | `/api/teacher/lessons/:id/complete` | 标记完成 |
| `POST` | `/api/teacher/lessons/:id/cancel` | 取消并释放课时 |

`Student` 增加 `archivedAt`。活跃学生查询、家长仪表盘和新建课程均排除已归档学生；历史课程和订单在审计视图保持可见。课程模型增加可选 `courseName`，默认“英语课”，用于手动排课和 AI 草稿的一致展示。

所有写操作使用 Zod 严格对象校验，拒绝未知字段；时间为带时区的 ISO 字符串，并经日历合法性、分钟精度、同年级、课时余额和教师冲突检查后才进入事务。任何客户端都不能写入课时总额、订单金额、支付状态或 `paidAt`。

## 前端组件边界

| 组件 | 责任 |
|---|---|
| `RoleGate` | 身份选择和会话内角色切换 |
| `TeacherShell` | 教师端导航与页面装配 |
| `ScheduleBoard` | 今日与周课表的时间行、状态行和日期导航 |
| `LessonSheet` | 新增、编辑、完成、取消课程的底部操作台 |
| `StudentDirectory` | 学员名单、搜索与档案抽屉 |
| `StudentSheet` | 新增、编辑、归档学生 |
| `ParentShell` | 单孩子主页、课程轨迹与课包入口 |
| `OrderTrail` | 模拟订单与支付状态展示 |

`App.vue` 只持有身份、加载状态和顶层数据刷新；每个工作台的请求、表单状态和可访问性焦点恢复放入对应组件或组合式函数。

## 错误、空态与可访问性

- 排课冲突直接指出冲突的时间和课程；余额不足指出对应学生。
- 学员为空时，唯一主操作是“新增学员”。
- 家长无可用学生时显示原因和返回身份选择的入口。
- 所有底部操作台使用 `dialog` 语义、焦点捕获、Escape 关闭及触发点焦点恢复。
- 触控目标不小于 44px；时间、状态和冲突不只依赖颜色。
- 小于等于 480px 优先验证；至少同时检查 390px 手机和 1280px 宽屏。

## 验证

1. 服务端单测覆盖学生新增、编辑、归档、课程编辑、分钟时间、同年级组合、冲突、余额和归档学生限制。
2. 客户端单测覆盖身份切换、时间输入、学生表单与操作台焦点恢复。
3. 浏览器端到端测试覆盖教师手动新建学生、创建 `09:30` 课程、编辑、取消、家长单孩子可见性与模拟支付文案。
4. 视觉检查捕获 390px 与 1280px 的教师端和家长端，确认无横向溢出、无卡片墙、时间列可读。

## 非目标

- 不接入真实微信支付或真实家长认证。
- 不允许教师确认订单或修改课时余额。
- 不支持一个家长管理多个孩子。
- 不实现已完成课程的追溯更正流程。
