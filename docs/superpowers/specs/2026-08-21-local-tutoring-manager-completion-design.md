# 补习班本机管理版设计规格

## 目标

在不部署上线、不接真实支付的前提下，把现有排课演示系统补全为本机可日常使用的补习班管理版：教师可维护学生、课时、订单与分钟级课程；家长只查看自己绑定的一个孩子并使用模拟支付。

## 边界

- 支付只有 `simulation` 和 `manual_qr` 两种本地记录方式；不调用微信支付、银行卡或任何外部收款服务。
- 页面及 API 使用中文；所有支付相关区域必须标示“模拟支付”或“扫码登记（模拟）”。
- 保留现有 AI “生成草稿—教师确认—写入课程”机制；AI 没有配置时必须如实提示，不能伪造成功。
- 本期不做公网部署、域名、短信、邮件、真实第三方登录或真正的多孩子家长端。

## 身份与访问

### 教师

- 本机登录页允许从已存在的教师／家长账号中选择身份进入；演示账号仍保留，但不是唯一入口。
- 教师拥有学生、课程、订单的完整管理权限。

### 家长

- 每个家长账户只绑定并返回一名学生；任何额外学生即使数据库存在也不得显示或被 API 访问。
- 家长只可查看自己的孩子、为自己的孩子发起模拟订单和完成模拟支付。

## 教师端

### 学生管理

- 列表显示姓名、年级、家长姓名、总课时、已预约、已完成、可用课时和状态。
- 教师可新增学生；录入姓名、年级、家长姓名、家长邮箱、初始总课时。
- 编辑只允许变更学生姓名、年级、总课时与家长资料；所有数值必须为非负整数，年级范围为初一至高三。
- 删除学生前必须确认；已有课程或订单的学生不做物理删除，而是标记为停用，历史记录仍保留且不可再排课／购买。

### 手动排课

- 课程创建表单包含：日期、开始时间（`HH:mm`，精确到分钟）、时长（默认 60 分钟）、同年级学生多选、课程备注。
- 支持同年级多个学生同一节课；不同年级不得组课。
- 服务端必须阻止教师时间冲突、学生时间冲突、课时不足、停用学生和非法日期／分钟。
- 教师可编辑尚未完成或取消的课程；编辑重新执行冲突和课时校验，不会重复扣课时。
- 教师可取消、完成课程；课程状态变化正确调整已预约／已完成课时。

### 订单与课时

- 教师可为某学生创建本地订单，选择内置课程包或输入“扫码登记（模拟）”的金额和课时。
- 付款只能由家长端或教师端明确确认一次；重复确认必须被拒绝，订单和课时余额保持一致。
- 教师可查看订单状态、付款方式、创建时间、付款时间、金额和课时；不允许删除已付款订单。

## 家长端

- 只显示绑定孩子的下节课、课程轨迹、课时余额和订单历史。
- 家长可选择内置套餐、创建模拟订单、确认模拟付款；不提供编辑学生、排课或跨孩子访问。
- 家长可看到“扫码登记（模拟）”说明和收款码占位区，但不会生成真实二维码支付请求。

## 数据模型与接口

- `Student` 增加停用状态与保留的家长显示信息；维护唯一的家长关联。
- `Lesson` 增加可选备注；课程编辑必须是事务性更新。
- 所有新增写接口由 Zod 校验，使用角色中间件和归属校验。
- 所有课时变更在 PostgreSQL 事务中完成，保证订单确认、课程新建／编辑／取消／完成的一致性。

## 用户界面

- 保持当前移动优先的“课堂时刻牌”与“家庭课程线”结构，不恢复桌面卡片墙。
- 教师端底部导航提供：今日、排课、学生、订单；表单采用全屏／底部抽屉式编辑体验，按钮高度至少 44px。
- 家长端保持单孩子连续轨迹，支付区域清楚标注为模拟。
- 所有弹层支持 Escape 关闭、焦点捕获和关闭后恢复焦点；遵守减少动态效果设置。

## 验收与测试

- 每项服务端写能力先有失败的单元／路由测试，再实现。
- 覆盖教师与家长的权限隔离、学生停用、学生 CRUD、同年级组合课、分钟级手动创建、课程编辑、冲突、课时余额、订单幂等确认和家长单孩子访问。
- 覆盖客户端表单校验、角色切换、焦点行为、模拟支付及 390px / 1280px 浏览器流程。
- 最终运行：客户端测试、客户端构建、服务端测试、真实 PostgreSQL Playwright E2E；全部通过后才声明完成。
